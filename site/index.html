How it works

The page solves

Our widget fetches a signed challenge and finds a nonce whose SHA-256 has enough leading zero bits. That takes a browser a fraction of a second; doing it millions of times costs a bot farm real compute.

The form carries a token

The solution is exchanged for a pass token that lives 5 minutes and is bound to your site key and domain. It lands in a hidden field, attestos-response.

Your server verifies once

Your backend posts the token and your secret key to /api/siteverify. The first call succeeds; any replay fails with timeout-or-duplicate.

// your backend (Node 18+)
const r = await fetch("https://attestos-edge.attestos.workers.dev/api/siteverify", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ secret: process.env.ATTESTOS_SECRET,
                         response: req.body["attestos-response"] }),
});
const v = await r.json();   // { success: true, hostname, method, … }
if (!v.success) return res.status(400).send("Bot check failed");

What proof-of-work does, honestly

  • Makes every automated submission cost CPU time, which kills cheap mass sign-ups, credential stuffing at scale and form spam floods.
  • Asks nothing of real visitors: no puzzles, no clicks, no third-party tracking cookies.
  • Single-use, short-lived, domain-bound tokens: a solved token can't be farmed and replayed.
  • It is not identity. A patient attacker with real compute can still pay the price, so keep server-side rate limits, and add the risk score or passkeys where it matters.
  • No tool can promise zero bots. We report what we check, and the verify response tells you how a token was earned.

Questions

Does it replace reCAPTCHA v2 / hCaptcha one to one?

Yes for the integration shape: a script, a hidden field and a siteverify call with success, challenge_ts, hostname and error-codes. The difference is that visitors see nothing.

What happens if AttestOS is down or my quota runs out?

You decide. The docs show a fail-open pattern for quota-exceeded and network errors, so your sign-ups never stop because of us.

Is visitor data sent anywhere?

The challenge is served from Cloudflare's edge. On paid IntegrityRuntime plans the widget also sends a few browser facts (listed in the privacy policy) to compute the risk score. No cookies, no cross-site tracking.
